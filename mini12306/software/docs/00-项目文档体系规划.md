## 1. 这份文档解决什么问题

本项目要跨 **6 次实验**逐步完成，如果每次实验临时决定写什么，很容易出现"文档互相矛盾、实验报告没素材、代码和文档对不上"。

所以先做一张**文档总图**：哪些文档要写、每份写什么、什么时候写、对应哪次实验。**本轮只出规划，不写正文**——正文留到对应实验时再写，避免过度设计。

## 4. 写作与格式约定

**统一约定（所有文档遵守）**

1. **中文写作**；技术标识符、代码、路径、枚举值、接口路径保持英文。
2. 每份文档开头带**文档头**：文档编号 / 版本 / 状态 / 编写人 / 评审人 / 更新日期 / 关联文档。
3. 图表规范：每张图必须有**编号与图题**（如"图 3-1 系统部署图"），每张表必须有**表头**。图用 Mermaid 写，便于版本管理与导出。
4. **禁止空话套话**（如"提高用户体验""性能良好"）；所有结论要么可验证、要么有编号可追溯。
5. **编号一经使用不复用、不重排**：需求 `FR-xx` / 非功能 `NFR-xx` / 业务规则 `BR-xx` / 测试用例 `TC-xx`。
6. 涉及个人信息的字段（身份证号、手机号、银行卡）在文档示例中**一律脱敏**（如 `110***********1234`）。
7. 不确定的信息统一写 `【待填：说明】`，**不留 TODO**。

**目录约定**

```
docs/           正式文档（DOC-00 ~ DOC-11）
docs/templates/ 实验报告与日志模板
report/         实验报告归档与 docx 导出产物
prototype/      静态 UI 原型（实验三起）
apps/web        前端工程（实验三起）
apps/api        后端工程（实验三起）
```

**导出**：所有 Markdown 文档用 pandoc 一键导出 docx，供实验报告直接引用或提交。
